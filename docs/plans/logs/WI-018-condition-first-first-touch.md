## DEVIATIONS

1. **Red flag → G3 is not invoked (`g3_eligible` gate, interpretation).** Plan step 3 says "a wall of survivors is flagged as a red flag, not a win" while step 4 says "invoke [G3] only for G2 survivors". Implemented as: `g2_pass` stays mechanical (survivors exist), but a new explicit `g3_eligible = g2_pass and not red_flag` gates G3, and `g3_skip_reason` records why. Justification: the plan's own words, the ADR's "ideal result: a small, explainable condition set reaching G3", and the impracticality of costing 2,506 conditions. **Flagged for the Planner + Hermes**: if the intent was to run the cost overlay on the red-flagged wall, that is a new order (and needs a cheaper bulk-IC path).
2. **Step-3 refactor of the G1/G2 state accumulator.** `atlas.collect_state_counts` now delegates to `streaming.stream_state_counts` (multi-target, shared with G2). One definition changed: breadth (`state_symbols`) now counts rows with a *defined state* instead of state-and-usable-primary-target, i.e. it is target-independent (includes ~0.86% rows whose target is null). All rates/CIs/coverage are unchanged; the committed G1 artifact was regenerated under the refactored code (see the step-2 refresh row) so `reports/wi018/atlas_USD.json` is reproducible from HEAD.
3. **Probe test fixture made stochastic.** The toy market's deterministic labels gave a constant per-date lift series (zero dispersion, correctly unevaluable under the new guard); 10% label noise restores a series the house estimator can score, and a dedicated test now locks the zero-dispersion convention.
4. **Artifact regeneration, not editing.** Both the probe and the atlas artifacts were regenerated by re-running their CLIs on the final code; nothing was hand-edited. The probe's first (pre-gate) run is kept at `/tmp/opencode/probe_pre_gate.json`; the diff vs the reported run touches only the gate fields plus `generated_utc` (one `nan -> nan` false positive), i.e. the run is recompute-verified.
